# Plan: M4x0.7 internal thread, 8 mm deep, in the 3.3 mm hole with the single-form thread mill: Machining Doctor inputs, offline conversion, tool change to the mill, one approved file job

## Findings before anything moves

- **The touch probe is in the spindle, not the thread mill** (`get_stored_state`). `convert_thread_milling_gcode` needs `tool_length_applied: true`, which means work Z0 already matches the thread mill's tip (thread-milling.md, "required declarations"). The converter removes G43/H and applies no length offset. So a tool change that keeps the origin true (tool-change skill) has to happen before the job, and I can't make that declaration truthfully until it's done.
- **Work Z0 depends on the tool that set it.** `originOffset` is present, set earlier today, but the store doesn't say which tool was fitted. Flow A only gives the right Z if the "old" measurement is the tool that set Z0. If Z0 was set with a tool that has since been removed and never measured on the setter, the chain is broken and Z0 has to be set again. I have to ask.
- **Hole clearance is tiny, so work XY has to be the measured hole centre.** An M4 single-form mill usually has a tooth diameter of about 3.0–3.15 mm. That leaves only ~0.08–0.15 mm of radial clearance in a 3.3 mm hole. The generator plunges straight down the hole centre at its rapid feed (the M2.5 fixture uses `G01 Z-5.056 F2000`). An origin set by eye would put the tooth into the hole edge. I need to know how X0 Y0 was set. Best case: the hole was drilled on this machine at this origin.
- **Reach decides whether this can be done at all.** The operator says the triple-form cutter has a neck "similar to the M2.5 one" (7.5 mm). A 7.5 mm reach can't cut 8 mm, because the D4 shank would reach the block top first. The single-form cutter's reach isn't stated. It needs about ≥ 8 mm + the tooth-to-tip distance + ~1 mm. Its neck diameter also has to clear the drilled wall while it orbits: orbit radius r = (4.0 − D_tooth)/2, and the neck needs d_neck < 3.3 − 2r. The converter's validation reports tool-centre bounds only, "not a swept cutter/holder clearance calculation" (thread-milling.md), so nothing downstream catches a neck or shank collision.
- **Hole depth.** 8 mm of thread needs a full-diameter hole at least 8 mm + tooth-to-tip distance + clearance deep. It's not stated whether the hole is blind or through.
- **The M2.5 program has two issues to raise now, before anyone runs it.** (a) The fixture header says `CUTTER DIAM=1.38`, but the operator describes 1.38 mm as the NECK. If the tooth is larger than 1.38, that program over-cuts the major diameter. The generator's cutter diameter must be the TOOTH diameter. (b) It says `L=2.25 [MULTI TOOTH]` and steps 2.25 mm per turn (0.056+0.45+0.056+1.688). Five pitches is 2.25 mm, but "triple row" at 0.45 pitch is ~1.35 mm, so that program would leave unthreaded bands. This doesn't affect the M4 job (single tooth, no cutting length), but the operator should know.
- **Flutes and thread forms are independent.** "Single thread (one tooth row)" is the axial form, i.e. the generator's "Single tooth" choice. It says nothing about the flute count, which the generator needs (thread-milling.md: "Do not infer one from the other"). I have to ask.
- **The spindle mode depends on the head type, and I don't have it yet.** `get_machine_profile` reports the toolhead. The README says the rig was verified with a 200 W head, but that's history, not a live reading. 200 W: `spindle_mode: "cnc_200w_rpm"`, and the generator's max RPM must stay within 8000–18000, because the converter refuses values outside that range and doesn't clamp. Standard head: `spindle_mode: "power_percent"` plus `spindle_power_percent`. The converter replaces the RPM but doesn't rescale feeds, so the generator's RPM has to be the speed the head really runs at.
- **The program's first move starts from an unknown point.** The file opens with `G00 X0 Y0` at whatever Z the head is at, then `G0 Z20` (work). Validation "excludes the unknown initial position" (thread-milling.md), so a file job gets no landmark check for that first XY leg. The rotary box (machine X110–230, Y130–342) sits beside the tool setter (X79, Y293). So I stage `goto_work_origin` at the park height first. It's a staged move that is checked against landmarks, and its confirm page shows the machine XY of work (0,0). The file's opening `G00 X0 Y0` then becomes a zero-length move.
- **The converter's other changes are expected.** It removes `M06 T1` (so the tool has to be fitted already), G43/H, G40/G41/D1 and the M08 coolant, and turns M30 into M5. So no coolant or air will run from the file; if the operator wants lubricant in the aluminium, they apply it themselves.
- **The removed probe can still trip the crash alarm.** A contact on a probe channel that no procedure expects, during MCP motion, trips the CRASH alarm (motion rules law 5). The removed touch probe has to sit where nothing can trigger it. The feed stays connected.
- **After the job, the head waits at work Z20 over the hole** (the program's last line). The next motion is `move_z` to machine Z328 on the operator's word (law 8 / law 3).

## Questions for the operator (one message)

1. **Single-form cutter dimensions:** tooth (cutting) diameter, neck diameter, reach (tip to shank, i.e. the usable depth), how far the tooth sits above the tip, and the number of flutes. If the reach is under ~9 mm, 8 mm of thread isn't possible with this cutter.
2. **The hole:** through or blind? If blind, how deep is the full 3.3 mm diameter? Was it drilled on this machine at the current work origin, so that X0 Y0 is the hole centre by construction? If not, how was X0 Y0 set?
3. **Work Z0:** is it the block top at this hole, and which tool was in the spindle when you set it: this touch probe, or something else?
4. **Tool change:** flow A, where I manage the offset (measure probe → park → you swap → measure the mill → shift work Z; four approvals), or flow B, the touchscreen wizard? What is the thread mill's protrusion from the collet (roughly; I'll declare it on the low side)? May I start the tool change as soon as you reply? The Machining Doctor file can come afterwards.
5. **Preflight:** are clamps within ~10 mm of the hole taller than 20 mm above the block top (the program rapids to work Z20 over the hole)? Are the door shut and extraction on? Will you lubricate the hole by hand?
6. *(Only if `get_machine_profile` reports the standard CNC head, not 200 W)* What spindle power % should the job use, and what RPM does your head actually give at that setting? I'll put that RPM into the generator, because the converter won't rescale feeds.
